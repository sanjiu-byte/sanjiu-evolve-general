# 项目记录模板

仅在没有可复用记录时使用必要部分，由 AI 填实际内容，存到使用者已授权位置。已有格式只补必要信息，不强制迁移。无接续需要不建任务卡，无新经验不造条目；原始资料仍按 [资料保存](资料保存.md) 留存。

## 项目入口

- 项目标识与真实位置：
- 当前有效方法与唯一记录负责人：
- 权威规则与资料入口：
- 项目默认、边界及本次历史整理的允许/排除范围：
- 当前任务记录入口：
- 完整资料保存位置、授权范围和排除项：
- 原文覆盖终点、成果/附件入口、缺项及远端备份状态：
- 方法版本、提交或快照定位：

“负责人”用于避免多个方法重复写同一经验，不表示必须增加人或搭建平台。原文、工作记录和方法安装目录分开；模板中的空白不是已完成配置。

## 一条可复用经验

- 可执行规则、适用条件与有依据的例外：
- 范围：该使用者跨项目 / 当前项目；本次例外写任务记录：
- 强度：硬约束 / 偏好；确认、暂行或候选状态：
- 来源原话或准确定位、来源时间、相关成果版本：
- 判断理由：用户明确 / AI 推断 / 未知；应保留的有效部分：
- 生效依据：明确要求 / 现行规则 / 三次提醒流程暂行加入：
- 效果证据：本次修正、后续应用、复发或待验证；实际检查层级：

只填有依据且有必要的信息，不为了字段齐全编造原因。首次后续应用或复发时按需补任务与时间、是否又被提醒、读取依据及成果定位；没有读取证据就写“结果符合，经验是否起作用未知”。修改同一条规则，别追加相反默认。

三次暂行机制仅按 [经验与接续](经验与接续.md) 的具体条件补独立来源、提问位置、后续状态；标清未获明确确认、可撤回、效果待验证。案例必要时补前版、反馈、后版和接受状态，未选候选不自动成为反例。用户说不记的内容不填写上述任何字段。

## 一张任务记录

- 任务标识、目标及父任务记录（分支时）：
- 当前适用核心要求原文或权威定位：
- 必须做到和保留的部分，偏好另标：
- 明确禁止或未经允许不改的部分及条件：
- 可以自行优化的关键范围：
- 已确认基线、当前工作版及各自接受状态：
- 本轮改变范围、仍有效例外与决定来源：
- 最新成果位置、当前进度、待办与未验证事项：
- 原始资料入口及本次覆盖缺项：
- 最后更新：

三类边界沿用原要求的范围、强度与来源，不另建三套正文，不强填无关项。未列出的常规细节仍可按目标判断，额外操作权限单独核对。任务卡保存当前有效状态，完整对话和各版成果另存；分支分卡并关联父卡，不覆盖父记录，新任务不继承上次的单次例外。
