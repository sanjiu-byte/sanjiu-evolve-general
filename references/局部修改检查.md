# 局部修改的可执行检查

已有 UTF-8 文本需要局部修改时，可用本工具冻结当前要求和修改范围，再由程序拼回完整文本，保留范围外的原始字节。AI 负责选对范围并检查语义；使用者不用填写 JSON 或学习命令。

## 什么时候用

适用于修改范围能定位为若干不重复片段、已有相应本地保存授权、可以运行 Python 3.9+ 的环境。代码优先采用项目现有补丁、格式检查和测试流程；不为使用本工具替换重构工具或改变工程结构。

新写内容、全文重构、二进制文件或无法可靠定位范围时，不套用局部修改流程。缺执行能力时直接对照改变项与保留项，不声称运行过程序。用户要求本轮不记时，不新建要求文件、快照或检查日志；按其范围完成当前成果。

真实输入和会话快照保存在使用者已授权的资料位置，不能写进分享用的方法包。已有范围不足以保存原文时，先按 [资料保存](资料保存.md) 处理。以下申请文档是虚构示例，不是用户经验或业务规范。

## 准备本轮材料

先读当前成果、最新要求正文和匹配任务记录，区分本轮改变项与保留项。基线可以是未确认草稿，但须保留真实状态；不把助手摘要当用户确认。

准备四个 UTF-8 文件。路径按实际工作目录确定，JSON 用序列化工具生成，保留原文的引号、BOM、空格与换行。

`baseline.txt`：

```text
申请说明
步骤一：先核对编号，然后提交申请。
步骤二：状态保持待审核，通知渠道不变。
```

`request.txt`：本轮实际原话；示例为“精简第一步的文字，保留先核对后提交的顺序，其他内容不变。”

`requirements.json`：本轮少量有效要求及来源。

```json
{"requirements":[
  {"id":"order","text":"先核对编号，再提交申请。","source":"本轮用户明确要求"},
  {"id":"status","text":"第二步状态和通知渠道保持。","source":"当前原稿与本轮保留项"}
]}
```

`scope.json`：允许替换的片段必须原样截取、非空、在基线中唯一出现，多个片段不能重叠；不把整个文件纳入局部修改。

```json
{"editable":[{"id":"step-one","text":"先核对编号，然后提交申请。"}]}
```

片段有重复时，用必要的相邻文字帮助定位，并在替换时保留这些额外文字。多个位置确需联动时分别列入范围；不要为了让新稿通过，事后扩大范围。

## 冻结、生成与核验

把 `<方法目录>` 换成真实安装目录，`python` 换成本机解释器。每次使用新会话目录；程序拒绝覆盖已有会话和稿件。

```text
python <方法目录>/scripts/edit_guard.py prepare --baseline baseline.txt --requirements requirements.json --request-file request.txt --scope scope.json --session edit-001
```

读取生成的 `edit-001/packet.md`，核对当前请求、要求、基线与范围。用 `edits.json` 提供每个允许 ID 的替换内容，恰好各一次；无需修改就填原文，确需删除才填空字符串。

```json
{"replacements":[{"id":"step-one","text":"核对编号后提交申请。"}]}
```

```text
python <方法目录>/scripts/edit_guard.py render --session edit-001 --edits edits.json --output candidate.txt
python <方法目录>/scripts/edit_guard.py check --session edit-001 --edits edits.json --candidate candidate.txt
```

读回 `candidate.txt`，核对允许范围内的意思、依赖关系及当前要求。代码片段仍须运行与改动相称的项目测试，文档仍须核对事实和适用条件。通过后按项目原流程交付或应用候选文件；程序不会覆盖源文件。

输入或要求已改变时，重新读当前依据并建新会话；不修改旧清单哈希来让过期结果通过。候选文件被额外修改会返回 `candidate_mismatch`，先查差异再修正。

## 结果能证明什么

- `scope_preserved` 证明候选文件等于允许替换拼回的文本，范围外字节保持；不证明范围选得正确。
- `semantic_check: not_evaluated` 表示工具没有判断事实、语义或业务质量。例如把第一步改成“直接提交申请”，字节范围检查可通过，但漏掉核对编号，成果仍不符合要求。
- 新鲜度检查只核验声明的四个输入及其快照；来源说明不会自动读取上游文件。上游规则变化后仍须由 AI 更新要求输入。
- 哈希用于发现输入漂移和误改，不是对恶意修改的安全认证。工具不联网、不运行输入中的指令，也不替用户积累或上传经验。

只汇报实际修改结果与必要限制，不把程序通过当成业务验收。新的可复用反馈继续按 [经验与接续](经验与接续.md) 处理。
