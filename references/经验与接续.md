# 经验与接续

处理实际需求、纠正与持续任务时使用。经验从当前使用者的真实工作中积累；本方法没有预装作者的业务偏好。先改善当前成果，再按授权更新适用经验。完整原文与各版成果另按 [资料保存](资料保存.md) 留存，短经验不能代替原件。

## 收到反馈后

1. 对照反馈发生时的有效要求，区分已有要求没落实、用户新增或改向、探索选择、工具实现问题；无法确定就保留未知。后来新增的要求不能倒算成前一版的错误。
2. 找到被评价的具体版本和位置，修正当前成果，并核对本轮改变项与仍有效的保留项，见 [任务边界与案例](任务边界与案例.md)。
3. 判断是否能复用、适用于该使用者跨项目、当前项目，还是仅本次。已有持久化授权时主动保存明确可复用的纠正，不必等三次；范围不清时只用于当前任务，必要时问一个影响后续的关键问题。
4. 更新已有条目，保留规则、适用条件、来源与生效依据；写前重读最新正文，合并并行变化，写后读回核验。没有新经验就不制造条目，但仍保存已授权范围内的新原始资料。

用户说“不记”时，按其范围不写入经验、候选、计数、任务摘要或采集日志，也不换成“反例”继续保存。明确允许“原文保留，但不加入经验”的，分开执行；不能声称已删除宿主自己保留的聊天。没有本地保存授权时先完成当前成果，再简单确认一次保存范围与位置。

## 把正负反馈变成有条件的判断

正反馈帮助保留有效部分，负反馈帮助发现不合适的条件。负反馈是线索，仍需回到具体目标、版本和理由，不能仅凭“不喜欢”建立全局禁令。

- 被评价的对象：是一句话、一个功能、一个流程，还是整体方向？保留前版位置、反馈原话、改后位置及后续接受状态。
- 理由：区分用户明确说出的理由、AI 推断和原因未知。AI 可以提出解释，但不能把推断记成使用者的真实判断。缺失理由不影响当前修改时先做；会造成不同改法时才澄清关键点。
- 保留项与条件：什么仍有效、什么目标受影响、何时适用、何时允许例外？没有证据的条件留未知，不为凑齐字段编造偏好。
- 可执行的改法：写清在什么条件下，应该保留什么、避免什么、可以怎样处理。只影响本项目的规则不升为跨项目默认；偏好不写成不可变禁令。
- 后续验证：本次修正是否落实与以后是否真正用上分别记录，见 [进化验证](进化验证.md)。已经有同一条规则却又没执行，先排查读取或落实问题，不增加同义禁令。

仅为说明机制的合成例子：用户要求把运营报告缩成一页，并否定删掉数据来源的改法。可以学习“在这一类报告中压缩重复解释，保留结论依据和来源”；不能学习“所有报告都必须一页”或“禁止摘要”。例子不进入使用者经验；真正的长期范围由其反馈决定。

## 三次提醒与暂行沉淀

仅在使用者已启用本流程并授权本地经验维护时使用。三次是提醒门槛，不证明是行业共性，也不产生完整对话保存、跨项目共享或上传权限。使用者可以关闭或改变此机制。

先检查是否已有生效规则。已有明确规则就直接执行并排查复发原因，不再次询问是否新增。尚未明确长期范围时，只有同一使用者、同一项目、相同窄条件下至少三次独立发生且有成果或反馈依据的问题，才提出本项目规则：

- 按独立处理机会计数；已得到修改机会，新成果仍出现同错可以再计一次。
- 同一错误连续催促三遍、复制同一条记录、分支继承、关键词重复或助手自述，不构成三次独立事件。
- 不拼接不同项目、矛盾要求、本次例外和“不记”内容；只核验可访问证据，不为凑数扫描全部历史。

第三次时主动问一次，并继续完成当前任务。例如：“这个问题已在本项目独立出现三次。要把〔具体规则和条件〕记为项目经验吗？可以说不加；如果之后继续提需求而未回应，我会按已启用的流程暂行加入，随时可撤回。”

| 后续情况 | 处理 |
| --- | --- |
| 明确同意 | 更新原条目，标为用户明确要求 |
| 明确否定或不加 | 不加入；相关暂行经验停止生效，不因次数增加继续推销 |
| 稍后再说、反问或纠正规则 | 保持待答复，继续澄清，不当成忽略 |
| 提问后继续交办其他需求，未回应此问题 | 核对无新否定或冲突，在原授权范围内加入可撤回的本项目暂行经验，完成当前工作后简短说明 |
| 仅时间过去、对话停止，或刚发出询问 | 保持待答复；不在提问同一回复中加入，不设计时器或后台写入 |

暂行条目保留三次独立来源、实际提问和后续继续工作未回应的依据，明确“未获确认、可撤回、效果待验证”。只影响相同条件下尚未明确规定的选择；当前明确要求、已确认规则与本次例外优先。用户后来否定就停止采用或修订，不倒改历史原文。否定、不记或关闭之后继续工作不算重新授权。不记内容连最小计数和否定标记也不保存；其他情形只有在授权范围内保留必要状态。

## 写入与后续复用

优先使用该使用者、该项目已有权威记录。没有记录时才用 [项目记录模板](项目记录模板.md) 的必要部分；真实内容不写进方法安装目录。多个方法同时存在时按当前项目已选的记录负责人执行，沿用同一原文定位与条目，不同时写两套。

每条经验分开保留：

- 生效依据：当前明确要求、现行项目规则或上述流程形成的暂行经验。普通助手推测保留候选，不当默认。
- 效果证据：本次修正、后续适用任务的实际落实、再次复发或未知。来源和日期能核验才填写；不能把 AI 检查写成用户验收。

下一次匹配任务开始时读取相关现行条目，交付时对照成果具体位置。首次后续复用、复发或范围变化时补充必要证据，不每次成功都追加日志。没有读取证据时只能记“结果符合，经验是否起作用未知”；仅没有再被提醒不算验证通过。

复发时先修成果，再检查：未读到、旧摘要覆盖、读到未执行、范围用错、输入缺失或工具没实现。只能确认哪一环就报告哪一环，不把所有问题归因为规则不够多。

## 检索与接续

先按项目和本次主题找现行正文，再读必要来源片段；需要解释旧决定时才追溯完整历史。明确必读资料不受检索排名影响。检查适用范围、版本与例外；找不到、读不到或存在冲突就说明具体缺项，不凭“已读取”保证检索完整。

持续任务沿用一张短任务记录，保留目标、核心要求原文或精确定位、当前基线与接受状态、本轮改变范围、有效例外、最新成果和待办。阶段或关键决定变化时更新，避免每轮重述完整方法；当前有效状态与完整原始资料分开。

新聊天、分支、压缩后或不确定加载状态时，重新核对技能入口、项目入口、匹配任务和当前用户要求。分支使用自己的任务记录并关联父记录，不覆盖父卡；新任务不自动继承上次的例外。匹配不明才澄清，不能把最后一张卡默认当当前任务。文件提供接续依据，不保证宿主强制加载或其他已打开聊天自动同步。

## 合并多人经验

仅在相应分享或汇总授权下整理。先核对真实来源、允许范围、重复与接受状态；完整私人资料留在各自已授权位置，分享包只含获准方法、空白模板与明确标注性质的示例。同条件的规则可合并，不同条件分别保留；冲突看目标与证据，不按人数投票。未验证结果保持候选，不自动覆写他人的经验或上传其聊天。
