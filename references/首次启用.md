# 首次启用与项目接入

仅在安装、首次接入实际项目或排查未生效时读取；日常工作按 [SKILL.md](../SKILL.md) 执行。目标是让使用者正常提需求和纠正，AI 完成需求核对、适用经验复用、资料保存与接续。

## 一句话启用后，AI 实际完成设置

标准启用请求：

```text
请从 https://github.com/sanjiu-byte/sanjiu-evolve-general （备用镜像 https://gitee.com/the-third-nine/sanjiu-evolve-general ）安装并配置 sanjiu-evolve-general，作为我以后新项目的默认进化方法，维护本地经验并保存相关对话原文、各版成果、反馈理由和附件；已有项目沿用已选方法和原资料，检查不要重复介入，并自行完成配置与保存核验。
```

此请求授权当前使用者范围内的安装、必要入口和相关本地记录。沿用已有授权目录；缺少位置或完整保存范围时按 [资料保存](资料保存.md) 只做一次基础确认。系统权限仍按实际工具处理；不由安装推导上传、全盘扫描、后台采集或其他人的配置权限。仅说“下载”时不扩展为安装和修改默认。

1. 按 [多平台接入](多平台接入.md) 查明当前宿主、持久化位置和真实能力，只配置本次平台。能自行查明就不让员工填技术表。无项目时先配置当前用户入口，项目首次开工再接入。
2. 检查该宿主已知技能入口及其实际链接目标。已有通用版就转入 [升级任务](../升级任务.md)，不另装第二份；只安装完整包，保留相对引用。若来源是本地开发目录，按根目录 `.gitignore` 中的具体文件白名单复制，排除 Git 历史、运行缓存和未发布资料。仓库连接失败时尝试另一镜像，已有完整包可复用；都不可用才给出必要下一步。
3. 将方法与个人资料分开。在获授权的稳定目录保存方法，经验和原文沿用本人已有位置；没有时推荐一个独立本地目录，不写入作者的账号或私有库。写入前确认真实资料不会进入未经授权的共享目录或 Git 提交。
4. 按下节确定各项目使用哪套方法，再合并一小段入口。写前读最新文件、保留可恢复副本，写后读回；保留其他业务约束和并行有效修改。
5. 验收方法可读、入口实际指向、已有记录保留、允许保存的本次资料真实落盘。尚无资料时写“保存位置已确定，待首次资料”，不能把空目录当归档成功。

## 与创作版共存：一个任务只运行一份进化流程

`sanjiu-evolve-general` 与 `sanjiu-evolve` 是两个独立产品，版本号独立比较；创作版及 self-evolve、project-evolve、team-evolve 等旧名不能当作通用版的旧安装覆盖。

- 当前明确选择优先。用户指定通用版，就用通用版；仅本次选择只影响本次，要求该项目以后使用才更新项目默认。
- 已有项目沿用其明确的方法入口与权威记录。安装通用版不自动迁移旧项目，不导入创作版的预置创作习惯。保留本使用者自己已确认、仍适用的项目需求，不能以“清空初始偏好”为由删除历史积累。
- 尚无选择的新项目采用已获授权的新项目默认。方法是否已安装，与项目选择了哪一套分开记录。
- 两套同时被发现时，按以上选择执行一次需求核对、一次经验维护和一份原文归档；其他套不再平行建立第二份记录。可以调用解决具体专业任务的其他技能，进化记录仍由本任务选定方法维护。
- 已有入口互相冲突且无明确选择时，保留原件，只问一次本项目使用哪套；能完成的业务工作继续做，重复记账先停。不能用当前对话口头选择掩盖仍同时生效的持久入口。

用户明确切换项目方法后，更新原有效项目入口，继续引用原资料位置，记录切换时刻与版本；不搬走、不删除旧方法正文，不复制一套私人经验。旧全局入口若写成“所有项目一律用创作版”，应在已获授权的默认配置范围内改为按项目选择分流，保留其他规则，不追加一条相互矛盾的“所有项目一律用通用版”。无法完成入口分流时报告冲突未解决。

## 用户级与项目级入口

在当前宿主实际加载的规则文件中合并简短入口，私人绝对路径映射只留本机。Codex 优先核对实际 `CODEX_HOME` 下的生效指令，Claude Code 核对其现有规则文件，其他平台按真实支持方式接入。不将整个方法全文塞进全局指令，不擅自更改使用者的禁用或仅手动调用设置。

用户级入口示例，写入前替换实际位置：

```text
已启用 sanjiu-evolve-general 作为尚未选择方法的新项目默认。已有项目沿用现行明确选择，用户本次指定优先；同一任务只由选定方法维护一份经验和资料记录。选中通用版时读取 <方法目录>/SKILL.md，核对项目有效要求、本人相关经验与匹配任务。反馈先修成果，再按授权保存原文、前后成果、理由及附件；个人、项目、单次范围分开，复用 <本人记录入口>，不上传或扫描未交给我处理的项目。新聊天或接续重新核对实际入口；普通闲聊不建台账。
```

项目首次真正开工时，读取现有项目规则与资料，沿用权威记录。无既有记录才按 [项目记录模板](项目记录模板.md) 建最少必要文件；项目内目录需同时确认被版本控制忽略且未被跟踪，不能保证时使用已授权的不入仓目录。先写并读回目标文件，再登记索引，避免留下假入口。

项目入口示例：

```text
本项目选择 sanjiu-evolve-general。开始或接续实质任务时读取本机已安装通用版的 SKILL.md，核对当前需求与本项目记录；沿用本机登记的唯一资料位置。其他进化方法不平行维护第二份记录，具体专业技能按需使用。保留本项目其他业务要求与用户本次例外。
```

## 权限、导入与失败处理

方法未发现、文件读取失败、目录不可写、临时云沙箱和工具初始化错误分别处理。检查真实返回，不能统一说成“文件不存在”或要求切 Full access。

确需用户操作时，说明用途、具体目标、当前实际按钮和获准后继续什么。例如弹窗确有该按钮时：“为了保存本项目资料，需要允许写入这个文件夹；请点 Allow once，我会接着保存并检查。”选择能完成任务的具体目录；不存在的目标需父目录授权时，申请最近必要父目录，不扩大到整盘。既有授权足够就直接继续，拒绝或未返回授权不写。

需要界面导入/替换时，AI 先准备完整包，再给员工必要的一步。只有当前宿主确实需要新聊天才能重新加载时才提示新开一次；不承诺所有已打开聊天即时更新。无法写文件时准备完整可导出文件或可复制内容，并明确尚未持久保存。资料保存受阻不阻断仍能完成的业务工作。

## 验收

由 AI 自查完整包与本次引用可读、版本明确、入口只有一个适用选择、原规则与资料仍在、实际写入文件可读回。脚本存在且本次需要时检查实际运行条件，不把帮助命令或静态检查当业务验证。可用隔离执行者时，在独立模拟项目做一次保存后接续，模拟规则不得写入真实偏好。

报告方法安装、资料保存和接续验证各自的真实状态；没有真实新上下文验证就说未验证。最后只告诉员工已完成什么、保存在哪里和唯一必要的下一步，不把检查工作推给员工。
